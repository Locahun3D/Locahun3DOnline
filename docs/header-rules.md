# ヘッダー設計ルール（両サイト共通・2026-07-28 制定）

ヘッダーは10回以上修正して「1端末を直すと別端末が崩れる」を繰り返した。
原因は個々の実装ミスではなく**構造そのもの**だったので、ここにルールを固定する。
ヘッダーを触る前に必ず読むこと。

対象: `locahun3d_online/src/components/site-header.tsx` と
`digiroke3d_Web/assets/site-header.css`（この2つが唯一のソース）。

## 何が起きていたか（2026-07-28 実測）

| 幅 | 構造 | トグル | ヘッダー高(online/scan) |
|---|---|---|---|
| <720px | **2段**・ナビそのまま | 8px / 2px 4px | 54 / 74 |
| 720–1023px | ハンバーガー | 9px / 3px 6px | 52 / 56 |
| ≥1024px | 1行フルナビ | 9px→11px(≥1200) | 52 / 56 |

iPhone 15 は縦390 / 横844。**回転すると720pxを跨ぎ、構造も寸法も別物になる。**
iPhone SE は横でも667pxなので**SEだけ横向きでも2段**。
端末ごとに落ちる帯が違うため、1帯を直すと別帯が壊れる。

## ルール

### R1. 構造は2つだけ。2段ヘッダーは作らない
- `<1024px` … ハンバーガー ＋ 中央ブランド
- `≥1024px` … 1行フルナビ ＋ 中央ブランド

2段構成は「同じサイトなのに構造が3種類ある」状態を生み、回転で別物になる元凶だった。

### R2. ブランド・トグル・EN の寸法は全幅で固定（最重要）
幅で文字サイズや余白を変えるかぎり、**回転で必ず見た目が変わる**。
縦と横で幅が違う以上、境界をどこに置いても必ず跨ぐ端末が出るため、
「跨がない境界を探す」は原理的に不可能。**寸法を変えないことが唯一の解。**

> 回転で「要素が増減する」ことは避けられない（幅が違う以上、入る数は変わる）。
> 避けられるのは「**同じ要素の見た目が変わること**」。後者を絶対に許さない。

### R3. 入り切らないときは「縮める」のではなく「ドロワーへ移す」
R2 の帰結。狭い画面では EN・カート・認証などをドロワー（ハンバーガーの中）へ退避させる。
**バーに残す要素は ☰ / ブランド / トグル の3つを最優先**とする。

### R4. 中央の定義は全幅共通＝「ブランド単体の水平中心 = 50vw」
- グループ（ブランド＋トグル）中央寄せは禁止。トグル幅の半分ずれ、両サイトで揃わない
- 基準は `100vw` の50%。`inset-x-0` だけだとスクロールバー予約分（15px）で両サイトが7.5pxずれる
  → `translateX(calc((100vw - 100%) / 2))` で戻す（online は zoom があるので `100vw/var(--z)`）
- ⚠ 中央グリッドは `absolute` なので **z-index を明示**する。右側グループが `flex-1` で
  行の中央から右端まで箱を広げており、`relative z-[1]` を持つため、
  z 指定を忘れるとブランドとトグルがクリックできなくなる（実測済み）

### R4b. 中央グリッドの左右列は必ず `minmax(0,1fr)`
素の `1fr` だと、内容を持つ列（トグル側）の最小幅が空の列より大きくなって
列が広がり、中央のブランドが押される。**両サイトで実際に起きた**
（online 375px:-10px / 320px:-37.5px、scan 375px:-16px / 390px:-8.5px）。
scan 側はトグルの `white-space:nowrap` を直して本来の幅に戻った途端に表面化した
（折り返していた間は幅が半分で偶然収まっていた）。
0まで縮む指定にすれば左右の列は必ず同幅になり、ブランドは常に画面中央に来る。

### R4c. 中央の基準に `100vw` を使わない（2026-07-29 追加）
`100vw` の意味はサイト設定で変わる。`scrollbar-gutter:stable` を敷いた
オンライン版では **予約分を除いた幅**（820px画面で805px）、敷いていない
スキャン側では **スクロールバー込み**（820px）になる。
同じ `translateX((100vw - 100%)/2)` が scan では +7.5px、online では 0 となり、
**実Chromeでブランド中心が両サイトで7.5pxずれていた**。

→ 中央は「**自分の箱の中央**」で取る。両サイトとも `scrollbar-gutter:stable` を
敷いて箱＝表示領域に揃えるので、ページの長短（スクロールバーの有無）でも動かない。
`translateX` による補正は不要になったため撤去した。

⚠ Tailwind の `translate-x-[calc((100vw_-_100%)/2)]` は**生成されず transform:none**
になっていた（実測）。arbitrary value の中で `calc` と `%` を混ぜるときは、
必ず実ブラウザで computed transform を確認すること。

### R5. 外周の padding だけは幅で変えてよい
要素そのものの見た目が変わらないため。狭い画面で横幅を稼ぐ手段はこれを最初に使う。

### R6. 同じ要素は両サイトで同一値。切替点も同一
数値を変えるときは**必ず両サイト同時**に。`header-parity.mjs` が機械照合する。

### R6b. Tailwind v4 の `max-[Npx]` は「N未満」
CSS の `@media(max-width:Npx)`（N を含む）と**1pxずれる**。両サイトで同じ境界に
したいときは `max-[(N+1)px]` を使う。1023px ちょうどで片サイトだけENが出る
不一致が実際に発生した（パリティ検査が検出）。

### R7. 検証は**実Chrome(headed)**で。ヘッドレスの結果を信用しない
ヘッドレスChromiumはスクロールバーが**重なり型**なので `100vw` と表示幅が一致し、
R4c のズレが**再現しない**。実際、ヘッドレスで580計測して「全幅ズレ0」と報告した
直後に、ユーザーが実Chromeで開いてズレを発見した。

```js
chromium.launch({ headless: false, channel: "chrome" })
```

数を測ることより、**現実を再現する環境で測ること**が優先。
併せてブラウザペイン（実Chrome）で要所を目視する。

### R7b. 触ったら本番でハーネス5本
```bash
node scripts/header-matrix.mjs       # ★実Chrome・全ページ×全端末×縦横の総当たり(500計測)
node scripts/header-live.mjs         # 本番・ブランド中心/重なり/はみ出し(軽い常用チェック)
node scripts/header-parity.mjs       # 両サイトの共有要素の computed style
node scripts/header-consistency.mjs  # スキャン19ページ×23幅が1pxも違わない
node scripts/ui-audit.mjs            # 26ページ×9幅の重なり・はみ出し
```
`header-matrix.mjs` の合格条件は「ブランド中心のズレ・ヘッダー高・トグルサイズが
**全計測で単一値**、横スクロール0」。1つでも複数値になったらページ差か端末差がある。

## 過去の失敗（同じ轍を踏まないために）

- **帯ごとに「中央の作り方」を変えた** → 1199→1200 の1px境界でブランドが84px飛び、
  PC帯では両サイトが26.8pxずれた（2026-07-28 修正）
- **上限を付けた中央機構**（`max-[1024px]` → `max-[1200px]`）→ 同じ失敗を2回。
  中央機構に**幅の上限を付けない**
- **切替点を下げたら、その帯だけに出ていた要素が消えた**（トグルが768–1279pxで消失）
  → 切替点を動かしたら、その帯域を必ずスクショで目視する
- **CSSを各HTMLへコピペ** → 3系統にdriftし「ページによって文字サイズが変わる」
  → `assets/site-header.css` 1本＋`sync_header.py` で同期

## R8: 検証は必ず「サインイン状態」でも行う

ヘッダー右側はサインイン時にだけ重くなる（EN / カート / 権限バッジ / マイページ /
通知ベル / アバター）。サインアウトのままでは右に余裕があるため、**実在する重なりが
1件も検出されない**。

実例（2026-07-29）: サインアウトで実Chrome・WebKit 各500計測が全て合格した直後、
サインイン状態で回したら即座に

- 1536px以上 … EN × アバター が 28px 重なり
- 1920px … EN × マイページ が 33.8px 重なり

が出た。原因は中央グリッドの列4に置いた EN で、列4の右端＝右グループと同じ位置に
なるため必然的に衝突する。EN は右グループ側へ一本化して解消した。

- `node scripts/header-matrix.mjs` … サインアウト（両サイト・端末縦横）
- `node scripts/header-signedin.mjs` … サインイン（オンライン版のみ・幅総当たり）

この2本は**対で回す**。片方だけでは合格の意味がない。

### サインインの作り方
サインアップ画面には Cloudflare Turnstile が入るため自動操作できない（迂回もしない）。
Clerk 公式のバックエンドAPIで検証用ユーザーと `sign_in_token` を発行し、
`/sign-in?__clerk_ticket=...` を開く。開発インスタンス（`sk_test`）専用。

⚠ `next start` は `.env.production.local`（本番鍵）を読むので、localhost では Clerk が
起動せずサインイン/サインアウトのどちらのUIも描画されない。検証は `next dev` に対して行う。

## R9: 中心ズレの基準は「ヘッダー自身の中心」

`document.documentElement.clientWidth / 2` を基準にしてはいけない。
`scrollbar-gutter: stable both-edges` の下では、スクロールするページ（clientWidth=375）と
しないページ（=390）で基準が 7.5px ずれ、**1pxも動いていないヘッダーが
「ページごとに違う」と誤検出される**（実測: `/cart` `/account` `/sign-in` だけ -59.6、
他は -52.1）。

また、測る対象は「ブランド＋トグルのまとまり」の中心にすること。ブランド単体だと
JA「ロケハン3D」124.5px と EN「Locahun 3D」131.5px の字幅差で必ず値が割れ、
中央ぞろえが正しいのに不合格になる。

## R10: works（web.locahun3d.com/works/**）はヘッダーを複製しない（2026-09-01）

本人指示「他のページと合わせる形にしたい。ヘッダーの複製に独立してパッチを
当て続けるのは構造的によくない、やめて」。

works は静的HTMLで、長らく `<header class="site-header sh-works">` ＋
`assets/works-header.css` という**別実装**を持っていた。オンライン版のヘッダーを
直すたびに works 側へ同じ修正を書き写す運用で、寸法や項目が延々とズレ続けた。

### 仕組み

```
locahun3d.com                              web.locahun3d.com（別リポ digiroke3d_Web）
  /partials/header-frame  ← ヘッダーだけを描くページ
  /partials/header        ← その HTML と CSS を Declarative Shadow DOM 1ブロックに
                            まとめて返す（route.ts / src/lib/header-partial.ts）
                                   │
                                   └── worker.js の injectOnlineHeader() が
                                       /works/** 配信時に HTMLRewriter で
                                       静的ヘッダーを丸ごと置換
```

- **works 側にヘッダーの数値を一切置かない。**見た目の調整はこのリポだけで完結する。
- 静的ヘッダーと `works-header.css` は**フォールバックとして残す**。部品の取得に
  失敗したら静的ヘッダーがそのまま出る（ヘッダー無しのページを絶対に出さない）。
- Shadow DOM に閉じているので works の記事CSSと相互汚染しない（実測: 記事本文の
  スクショはフォールバック時と1pxも変わらない）。

### 落とし穴（実際に踏んだ）

| 症状 | 原因 |
|---|---|
| ヘッダー下の1pxボーダーが消える（56→55px） | `@property` は @font-face と同じく document スコープで Shadow DOM 内では登録されない。`var(--tw-border-style)` が無効化される。Tailwind が出している `@layer properties` の @supports フォールバックのゲートを外して解決 |
| @font-face が漏れる / `@layer properties` ごと落ちる | ビルド後CSSは at-rule の直前にコメントが付く。prelude をコメント込みで判定すると at-rule と認識できず、コメント内の `.module.css` をクラス名として拾ってしまう |
| ヘッダーが56px下がる | 旧ヘッダーが position:fixed だったため各 works ページに `body{padding-top:56px}` がある。差し替え後は sticky なので、置換したページに限り打ち消す |
| CSS変数が全部効かない | Shadow 内では `:root` が何にもマッチしない。`:root`/`html`/`body` を `:host` へ寄せる |
| ヘッダーが 1.25 倍で描かれる | `html{zoom}` はページ側の指定。works に zoom は無いので `zoom`/`--z` 宣言を落として `:host{--z:1}` を与える |
| position:sticky が効かない | ホストに箱があると sticky がその高さに閉じ込められる。`:host{display:contents}` |

### 制約
- 認証状態は載せない（Cookie を転送せずキャッシュ可能にするため）。works のヘッダーは
  常に未ログイン形（EN / カート / ログイン / 新規登録）。ログイン/新規登録は
  最小のシムで `locahun3d.com/sign-in` `/sign-up` へ遷移する（モーダルは出ない）。
- works ページでは React が動かないので、ハンバーガーの開閉も同じシムが担当する。
  `header-tablet-nav.tsx` の開閉クラスを変えたら `src/lib/header-partial.ts` の
  `DYNAMIC_CLASSES` とシムを対で直すこと。
