# アップロード済み3DGSのオンライン編集

## 承認済みの目的
物件編集の3DGS欄から既存ビューアーを開き、区画・パス、配置・向き、追加画像を編集し、同じシーンへ保存する。元ファイルを失わない。新しいシーンを増やさない。

## 構成
- 各シーンのプレビュー横に「編集」を追加。保存済みの物件IDと安定したシーンIDで編集対象を解決する。未保存の追加シーンは先に物件保存を求める。
- サーバーで管理者または当該物件の編集権限を確認する。クライアントのIDやURLだけを信用しない。閲覧用の課金・解除処理は呼ばない。
- 既存ビューアーの区画・パス、移動・回転、画像追加、プロジェクト保存を利用する。新しい編集UIの重複実装や、他のビューアーデザイン変更は行わない。
- 編集セッションは物件ID、シーンID、元URL、物件リビジョンに結び付ける。既存の下書き転送経路を公開物件にも無条件で開放せず、編集専用の検証経路を設ける。

## 保存
1. 既存プロジェクトZIPを復元する。単体3DGSの場合は新規プロジェクトとして読み込む。復元が不完全な場合は保存を許可しない。
2. 編集内容と追加アセットを保存可能なプロジェクトにまとめ、新しい保存キーへアップロードする。元キーは上書き・削除しない。
3. アップロードの完了・内容整合性を確認した後、対象シーンだけを条件付き更新する。同時編集・削除・差し替えがあれば競合として停止する。
4. シーンID、価格、販売用ファイル、閲覧権限、物件公開状態は変更しない。閲覧用シーンのURLとサイズを更新し、旧URLを復旧用に保持する。
5. 公開済み物件では、保存成功後の閲覧から更新が反映されることを保存ボタン付近に明示する。

## 失敗時
通信切断・認証切れ・保存競合では旧シーンのままとし、編集画面には未保存状態と再試行方法を表示する。閉じる・再読込時は未保存警告を出す。成功通知はサーバーの紐付け完了後にのみ表示する。競合は自動で強制上書きしない。

## 検証
- 権限なし、別物件、削除済みシーン、期限切れセッションの拒否。
- 転送失敗と同時保存で旧URL・販売情報・公開範囲が維持されること。
- 実際の3DGSに区画・パス、移動・回転、画像を加え、保存後に新しく開き直して見た目と編集値が保持されること。
- PC1440・iPad820・スマホ390で編集入口と保存状態を画像確認。タッチでの操作は対応範囲を明記する。
- 既存のビューアー成果物の未コミット変更を保護し、ソースからのみビルドする。本番push・デプロイは別途指示待ち。

## 実装前の確認点
既存シリアライザーの画像保存対応と大容量ZIP生成時のメモリ使用をコードと実データで確認する。対応していない要素を黙って欠落させない。初回は完全プロジェクト保存を基本とし、差分アセット保存の最適化は別工程とする。

## 実装で確定した制限（2026-09-19）
- 販売用データ（downloadFileUrl 等）は変更しない。編集画面に「ビューアー表示だけに反映され、販売用データは変わらない」旨を常時表示する。
- 公開中の物件のシーン保存・履歴からの復元は管理者のみ。物件オーナー（studio）は下書き物件のシーンだけ編集・保存できる。
- 編集できる元ファイルは 1GB まで（環境変数 `SCENE_EDIT_MAX_SOURCE_BYTES` で変更可）。超える場合は開く前に理由を表示して止める。
- 編集履歴は「最初の版＋直近4版」を保持する。外れた版は履歴保護が外れ、未使用ファイル整理で削除できる。未反映のアップロードは編集セッション期限＋24時間だけ保護する。
- 管理者は物件編集画面の「オンライン編集の履歴」から任意の保持版に戻せる。戻す直前の表示も履歴に残るため、戻す操作自体も取り消せる。
- 履歴に残した元ファイルは、管理画面の「差し替え」でも上書きできない。
- 保存後の照合ダウンロードは、ブラウザが大きな塊でデータを渡しても失敗しない（総量のみ上限で検査）。
